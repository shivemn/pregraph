Designs / Core

Design a chat app

Like WhatsApp, Telegram, Discord and SlackCore

Every phone keeps one connection open to a gateway, so the server can push a message the moment it arrives. A message service checks it, gives it an ID that sorts by time, stores it and sends it to whichever gateway holds the recipient. If the recipient is offline, a push notification wakes their phone. The hard parts are never losing a message, never showing it twice, and keeping order.

    What it must do

    Features

    • One-to-one and group chats
    • Sent, delivered and read ticks
    • Photos and files
    • Online and last seen
    • Messages wait for offline phones

    Qualities

    • Delivered in well under a second
    • Never lost, never shown twice
    • In order within a chat
    • Light on battery and mobile data
    • Keeps working when a server dies

    Rough numbers

    Our assumption for a mid-size app: 100 million people a day, 40 messages each. These are not WhatsApp's figures.

    WhatSizeHow we got it
    Messages46,000 a second4 billion a day ÷ 86,400 seconds. Plan for about three times that at peak.
    Text stored800 GB a dayAbout 200 bytes per message with its details. Only if you keep history, which WhatsApp does not.
    Open connections30 millionSay 30% of daily users are online at the busiest moment.
    Gateway servers60 to 300100,000 to 500,000 connections each, leaving room for a server to fail.

    At real scale

    WhatsApp said in 2020 that it delivers roughly 100 billion messages a day, about 25 times our example, but deletes each one from its servers once it is delivered.

    Discord keeps every message forever. By 2023 that was trillions of messages on 72 database nodes.

    Key decisions

    • Open connection, not pollingA WebSocket or long-lived TCP connection lets the server push at once. Asking "anything new?" every few seconds is slow and drains the battery.
    • Server-made IDsPhone clocks are wrong. IDs that sort by time (timestamp, machine, sequence, as in Twitter's Snowflake) give one order everyone agrees on.
    • Store by chatThe common read is "latest messages in this chat", so a wide-column store partitioned by chat and time window beats one big SQL table.
    • Keep or deleteDeleting after delivery (WhatsApp) or keeping forever (Discord, Slack) is a product choice. It changes storage by orders of magnitude.
    • End-to-end encryptionThe server can't read messages, so search and backups move to the phone.
    • Big groups pullPush each message to small groups. In huge channels, members fetch recent messages when they open the chat.

    What breaks first

    • A gateway restarts. Hundreds of thousands of phones reconnect at once. Phones wait a random, growing delay before retrying.
    • One chat gets huge. Its partition is overloaded. Split by time window and merge identical reads, as Discord does.
    • New Year's Eve. Push notifications spike. Collapse several messages into one notification and queue the rest.

    How the real ones built it

    What each company has published about its own system.

    WhatsApp

    In 2012 a single Erlang server held over 2 million open connections. Messages are end-to-end encrypted and leave the server once delivered. Each linked device has its own keys, so a sender's phone encrypts a copy for every device.

    • 1 million is so 2011 WhatsApp blog, 2012
    • How WhatsApp enables multi-device capability Meta Engineering, 2021

    Discord

    Keeps every message. Moved from MongoDB to Cassandra, then to ScyllaDB. Its real-time gateway runs on Elixir.

    • How Discord stores billions of messages Discord, 2017
    • How Discord stores trillions of messages Discord, 2023
    • How Discord scaled Elixir to 5,000,000 concurrent users Discord, 2017

    Slack

    Channel servers keep recent channel state in memory and are found by consistent hashing. Gateway servers in each region hold the WebSockets.

    • Real-time messaging Slack Engineering, 2023

    Messenger

    Moved phones from asking for updates to being sent an ordered stream of changes, which cut data use and made sync faster.

    • Building mobile-first infrastructure for Messenger Facebook Engineering, 2014

    Telegram

    Publishes its protocol, MTProto, rather than its server design. Ordinary chats are stored on its servers so every device syncs. Only Secret Chats are end-to-end encrypted.

    • MTProto protocol Telegram
    • Secret chats FAQ Telegram
